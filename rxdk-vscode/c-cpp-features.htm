C/C++ Features

RXDK builds your title against a from-source C runtime (picolibc) and C++ runtime (libc++ / libc++abi), so the standard library behaves as you'd expect. On top of that it adds a small set of first-party runtime hooks: registration points a title (or libxapi) installs a callback into, so the C library can route console input, program output, image launching, and crash reporting through your code.

The reason these are hooks rather than fixed behavior: libc deliberately stays kernel-only — it can't own platform policy like “where does console input come from” or “how is another XBE launched” without guessing or depending on higher layers. Instead it exposes the callbacks below. With no handler registered, libc falls back to a safe default (EOF for input, DbgPrint for output, ENOSYS for exec), so a title that never sets a hook still links and runs.

A full C/C++ runtime on a non-terminal console

The original Xbox has no shell, no TTY, no OS-level environment, and no process model — so a lot of everyday C/C++ plumbing has, by default, nowhere to go. RXDK's from-source runtime (picolibc for C, libc++ / libc++abi for C++, plus the Xbox API) nevertheless implements a large, standards-conformant slice of it, kernel-backed where it needs to be. Much of this is easy to overlook because you wouldn't expect it to exist on this hardware. Highlights:

Threading, memory & time guarantees

  • Per-thread errno and thread-safe malloc/free under contention (picolibc's allocator locks were retargeted for thread safety).
  • Cooperative fibers — ConvertThreadToFiber/CreateFiber/SwitchToFiber/DeleteFiber.
  • Kernel-backed heap far beyond a small static heap (commit-on-demand, multi-MiB allocations), plus Win32 VirtualAlloc/HeapAlloc.
  • Monotonic vs wall-clock: clock_gettime(CLOCK_MONOTONIC) vs gettimeofday vs clock(), and xAPI QueryPerformanceCounter.
  • Win32 threading/sync/TLS (CreateThread, CRITICAL_SECTION, events, Interlocked*, TlsAlloc) alongside the C/C++ primitives.

Gotchas worth knowing

  • POSIX/GNU visibility: the clock API (clock_gettime, CLOCK_MONOTONIC) is gated behind __POSIX_VISIBLE/__GNU_VISIBLE — under -std=c23, define _GNU_SOURCE (or _POSIX_C_SOURCE) to see it.
  • Exceptions vs -fno-exceptions: the runtime supports EH, but the SDK builds titles -fno-exceptions by default — prefer the error_code overloads (<filesystem>, <charconv>) unless you opt exceptions back in.
  • Non-blocking sockets on a dev kit: with libxnet, a blocking socket call can starve the DPC-driven network stack — set ioctlsocket(FIONBIO) and drive sockets non-blocking.
  • MSVC printf quirks: _snprintf/_vsnprintf keep the non-C99 semantics ported titles rely on (no NUL-terminate when full, return -1 on truncation).

libc I/O + process hooks

Declared in <xbox/libc_hooks.h>. Each rxdk_set_*_handler() installs a C function pointer; passing NULL restores the default. The handlers use POSIX-style signatures (ssize_t / size_t from <sys/types.h>).

Console input (the getch / stdin hook)

read(fd 0, buf, count) — and everything layered on it (getchar, scanf, fgets(…, stdin), std::cin) — calls your handler. Return the number of bytes written into buf, 0 for EOF, or -1 for an error. This is where you feed characters from a USB keyboard, a debug channel, or a scripted test. 

#include <xbox/libc_hooks.h>
#include <string.h>

/* Supplies bytes to read(0)/getchar()/std::cin. */
static ssize_t my_stdin(void* buf, size_t count)
{
    const char* line = "hello\n";
    size_t n = strlen(line);
    if (n > count)
        n = count;
    memcpy(buf, line, n);
    return (ssize_t)n;   /* 0 = EOF, -1 = error */
}

rxdk_set_stdin_handler(my_stdin);   /* rxdk_set_stdin_handler(NULL) restores EOF */

Program output (printf / stdout / stderr)

write(1,…) and write(2,…) — the sinks behind printf, fputs, fprintf, and std::cout/std::cerr — route to your handler instead of DbgPrint. The fd argument tells you which stream it was (1 = stdout, 2 = stderr). Return the number of bytes consumed. Use this to draw a console overlay, log to a file, or forward output over the network. 

#include <xbox/libc_hooks.h>
#include "xbox/kernel.h"

/* Everything printf()/std::cout writes arrives here. */
static ssize_t my_output(int fd, const void* buf, size_t count)
{
    DbgPrint("[fd %d] %.*s", fd, (int)count, (const char*)buf);
    return (ssize_t)count;   /* bytes written */
}

rxdk_set_output_handler(my_output);
printf("hello from RXDK\n");   /* -> my_output(1, "hello from RXDK\n", 16) */

Launching another image (exec)

execve(path, argv, envp) calls your handler, which is where you hand off to the Xbox launch API. Like execve, a successful launch does not return; return -1 (and set errno) on failure. All three arguments — the image path, the NULL-terminated argv, and envp — are passed straight through. 

#include <xbox/libc_hooks.h>
#include "xbox/kernel.h"

static int my_exec(const char* path, char* const argv[], char* const envp[])
{
    (void)argv;
    (void)envp;
    DbgPrint("launch: %s\n", path);
    /* ... hand off to the title-launch API ... */
    return -1;   /* only returns on failure, like execve */
}

rxdk_set_exec_handler(my_exec);

Catch-all unhandled C++ exception

RXDK's C++ runtime provides the standard <exception> machinery, so the catch-all for an uncaught exception is ordinary C++: install a handler with std::set_terminate. std::terminate fires when an exception escapes main with no matching catch, or when stack unwinding can't find a handler. Without a handler an uncaught throw halts silently; a terminate handler lets you report it (over the debug monitor) and park so a debugger can attach. 

#include <exception>
#include "xbox/kernel.h"

/* Fires on an uncaught throw, or when unwinding finds no handler. */
static void rxdk_terminate()
{
    DbgPrint("RXDK: std::terminate -- unhandled C++ exception\n");
    for (;;)
        ;   /* park so the debugger can attach */
}

int main()
{
    std::set_terminate(rxdk_terminate);
    /* ... your title ... */
}

Other exception & signal entry points

These also exist but are secondary to the paths above:

  • Win32 top-level SEH filter — SetUnhandledExceptionFilter() (from <winbase.h>) installs a structured-exception filter that runs when no __try/__except handles a hardware/structured exception. Use it for a native crash handler where you want the faulting context (EXCEPTION_POINTERS) rather than a C++ throw.
  • POSIX signals — signal(sig, handler) (from <signal.h>) registers a C callback for signals such as SIGTERM/SIGINT raised via raise().
