rxdk.project.json — Project Manifest Reference

Every RXDK project has an rxdk.project.json file at its root. The extension locates a project by searching the workspace for this file; it drives the build (which sources/libraries to compile), the PE→XBE image step (imagebld switches), and deploy (what to copy to the console).

There are two kinds of project:

  • Source project — RXDK compiles your sources and links libraries into an .xbe.
  • Prebuilt-XBE project — you point at an existing .xbe (+ optional .pdb/.map); RXDK skips the build and only deploys + debugs. Set the prebuilt object for this mode (see Prebuilt-XBE projects).

Minimal example

This is the layout the RXDK: New Project templates generate: shared fields at the top level, and a configurations object with one block per configuration, each naming its own SDK libraries (Debug and Release variants are different files). 

{
  "name": "my-triangle",
  "sources": ["src/main.cpp"],
  "defaultConfiguration": "Debug",
  "configurations": {
    "Debug": {
      "configuration": "debug",
      "libraries": ["libd3d8d.lib", "libd3dx8d.lib", "libxapid.lib", "libcd.lib", "libcppd.lib", "libkerneld.lib", "libcompatd.lib"],
      "outputDir": "out/Debug",
      "imageBuild": { "stackSize": 65536, "debug": true, "noLogo": true, "noLibWarn": true }
    },
    "Release": {
      "configuration": "release",
      "libraries": ["libd3d8.lib", "libd3dx8.lib", "libxapi.lib", "libc.lib", "libcpp.lib", "libkernel.lib", "libcompat.lib"],
      "outputDir": "out/Release",
      "imageBuild": { "stackSize": 65536, "debug": true, "noLogo": true, "noLibWarn": true }
    }
  }
}

Full example (media + embedded file + extra include/defines)

Any field may sit at the top level (shared by every configuration) or inside a configuration block (that configuration only); a field set in the block replaces the top-level one. 

{
  "name": "my-tone",
  "sources": ["src/main.cpp", "src/audio.cpp"],
  "includePaths": ["include"],
  "defines": ["MY_FEATURE=1"],
  "deployPaths": ["media"],
  "embed": [{ "path": "media/dsstdfx.bin", "name": "dsstdfx" }],
  "imageBuild": {
    "stackSize": 65536,
    "debug": true,
    "noLogo": true,
    "noLibWarn": true,
    "limitMemory": false,
    "noPreload": [".data"]
  },
  "defaultConfiguration": "Debug",
  "configurations": {
    "Debug": {
      "configuration": "debug",
      "defines": ["MY_FEATURE=1", "AUDIO_DEBUG"],
      "libraries": ["libdsoundd.lib", "libxapid.lib", "libcd.lib", "libcppd.lib", "libkerneld.lib", "libcompatd.lib"],
      "outputDir": "out/Debug"
    },
    "Release": {
      "configuration": "release",
      "libraries": ["libdsound.lib", "libxapi.lib", "libc.lib", "libcpp.lib", "libkernel.lib", "libcompat.lib"],
      "outputDir": "out/Release"
    }
  }
}

Single-configuration (flat) manifests

configurations is optional. A manifest without it is a single implicit configuration: every field is read from the top level, exactly as written. The top-level configuration flag still decides how your sources are compiled, and the top-level libraries are still linked verbatim — nothing is renamed for you, so a flat Debug manifest has to spell the Debug files itself: 

{
  "name": "my-triangle",
  "sources": ["src/main.cpp"],
  "configuration": "debug",
  "libraries": ["libd3d8d.lib", "libd3dx8d.lib", "libxapid.lib", "libcd.lib", "libcppd.lib", "libkerneld.lib", "libcompatd.lib"],
  "imageBuild": { "stackSize": 65536, "debug": true }
}

Top-level properties

name

Type: string · Required

The project/title name. Used as the output .xbe/.exe/.lib base name and as the remote folder under xe:\ on the console (xe:\<name>\). Use a filesystem-safe name (letters, digits, _, -; start with a letter).

type

Type: "executable" | "library" | "dxt" · Optional (default "executable")

"executable" builds an .xbe. "library" builds a static <outputDir>/<name>.lib that other projects link via projectReferences; a library is not deployed or run. See Multi-project builds. "dxt" builds a debug-monitor extension (.dxt, entry point DxtEntry) instead of an XBE.

sources

Type: string[] · Source projects only

Project-relative paths to the .c / .cpp files to compile. Globs are not expanded — list each file. A source ending in .cpp/.cxx/.cc marks the project as C++ (pulls in the C++ toolchain and IntelliSense configuration). Example: ["src/main.cpp", "src/render/mesh.cpp"]

libraries

Type: string[] · Source projects only · Usually set per configuration

RXDK-SDK libraries to link, named exactly as the files in the SDK's lib folder, including the .lib extension — like a Visual Studio Additional Dependencies list. The names are used verbatim: RXDK never adds the .lib extension or the Debug d suffix for you. The SDK ships both variants of every library side by side in one folder; the Debug one has a d before the extension (libd3d8.lib / libd3d8d.lib, libxapi.lib / libxapid.lib, libc.lib / libcd.lib, libcpp.lib / libcppd.lib, libkernel.lib / libkerneld.lib). That is why the Debug and Release configurations each carry their own list.

Names are looked up in the SDK lib folder first, then in each libraryPaths directory; a name that isn't found fails the build (Missing library). Duplicates are dropped and libcompat.lib/libcompatd.lib is always linked whole-archive ahead of the rest. libkernel.lib is moved to the end, but only under that exact name, so list libkerneld.lib after the other libraries yourself. Everything else links in the order listed. Common libraries (Release name; the Debug file adds d):

LibraryProvides
libd3d8.libDirect3D 8 (graphics)
libd3dx8.libD3DX 8 math/texture helpers
libxgraphics.libXGraphics helpers, including the XFONT bitmap-font API (xfont.h)
libdsound.libDirectSound (audio)
libxact.libXACT audio engine
libdmusic.libDirectMusic
libxapi.libXbox API (threads, files, input plumbing, launch). Linking it (either spelling) makes the title start at XapiTitleStartup, which sets up the xAPI drives before main.
libxmv.libXMV video playback
libxnet.libXNet TCP/IP networking + Berkeley sockets
libxonline.libXbox Live (online) services
libxbdm.libDebug monitor API (xbdm.h; DXT projects link it)

The SDK's lib folder also holds libxneto, libxvoice, libuix and libd3d8i (each with its …d.lib Debug file); check that folder for the exact names.

List libcpp.lib (Debug: libcppd.lib) whenever you link a C++ SDK library, even from a C-only project. Several SDK libraries are written in C++ and call into the C++ runtime: libxapi, libdsound, libd3dx8, libxgraphics, libxact and libdmusic. Without libcpp the link fails with undefined operator new/delete or RTTI symbols. The same goes for a library project that uses one of them: whichever project performs the final link has to list libcpp.

libraryPaths

Type: string[] · Optional

Extra directories (project-relative or absolute) searched for libraries names, after the SDK lib folder. Use it to link your own prebuilt libraries by name.

additionalLibraries

Type: string[] · Optional

Prebuilt static-library files linked by path (project-relative or absolute), in addition to libraries. A missing file fails the build. They must be built for the original Xbox target.

configuration

Type: "debug" | "release" · Optional (default: release) · Source projects only

Whether this project's own sources are compiled as Debug or Release: debug compiles unoptimized with debug info (-O0 -g); release compiles optimized (-O3). Inside a configurations block it is what makes that block Debug or Release — the block's name doesn't. Omitted means release, so a block called "Debug" without "configuration": "debug" builds optimized.

This flag does not pick the SDK library variant. The Debug/Release SDK libraries are chosen only by the file names you list in libraries, so keep the two in step ("configuration": "debug" alongside the …d.lib names). The RXDK: Set Build Type setting (rxdk.optimize) is not used by RXDK: Build; the optimize level comes from this field.

configurations

Type: object (configuration name → manifest fields) · Optional

Named build configurations, usually "Debug" and "Release". Each value is a partial manifest; when a configuration is built, every field it sets replaces the top-level field of the same name, and every field it leaves out falls back to the top level. Lists replace rather than merge: a block's libraries or defines are the whole list for that configuration. Any field can be overridden this way; the templates put configuration, libraries, outputDir and imageBuild in each block.

Pick the configuration to build with RXDK: Select Configuration. Names are matched case-insensitively. If none is selected, RXDK uses defaultConfiguration, or the first configuration listed. Without configurations the manifest is a single flat configuration.

defaultConfiguration

Type: string · Optional (default: the first key in configurations)

The configuration to build when none has been selected, e.g. "Debug".

projectReferences

Type: string[] · Optional · Executable or library projects

Project-relative paths to library projects (folders whose rxdk.project.json has "type": "library") that this project links. Resolved transitively (a library may reference other libraries), built in dependency order to static .libs, then linked into this project. Each referenced library's publicIncludePaths are added to this project's compile include path automatically, and its SDK libraries are merged into the final link. Example: ["../libs/physics", "../libs/render"]. See Multi-project builds.

includePaths

Type: string[] · Optional

Extra project-relative include directories, passed to the compiler as /I after the SDK's include. Private to this project's own compile. Example: ["include", "third_party/include"]

publicIncludePaths

Type: string[] · Optional

Include directories a library project exports to projects that reference it — they are added to the consumer's compile include path (transitively). Also visible to the library's own sources. For an executable this behaves like an extra local include path. Example (in a library): ["include"]

defines

Type: string[] · Optional

Extra preprocessor defines (/D), appended after the RXDK defaults. Use NAME or NAME=value. Example: ["NDEBUG", "TITLE_ID=0x1234"]

outputDir

Type: string · Optional (default: out)

Project-relative directory for build artifacts (.exe, .xbe, .pdb, .map, intermediate objects).

deployPaths

Type: string[] · Optional

Project-relative files or directories copied next to your title's own output — to xe:\<name>\ on RXDK: Deploy, and staged into the .iso alongside default.xbe on RXDK: Build. Use for runtime assets your title loads (textures, sounds, video).

  • A directory entry is copied recursively, preserving its structure under that same name. Example: ["media", "data/levels"] → xe:\my-title\media\…, xe:\my-title\data\levels\….
  • A file entry is copied to that exact same relative path. Example: ["readme.txt"] → xe:\my-title\readme.txt.
deployPaths vs embed: deployPaths copies loose files to the console filesystem / disc image (read at runtime from disc/HDD). To bake a file into the XBE image instead, use embed.

embed

Type: RxdkEmbedFile[] · Optional

Files embedded inside the XBE at build time via imagebld /insertfile. Retrieve them at runtime by the given resource name. Typical use: the DirectSound standard-effects blob (dsstdfx.bin). Each entry:

  • path — string, required. Project-relative path to the file to embed.
  • name — string, required. Resource name the title uses to locate the embedded data.

Example: [{ "path": "media/dsstdfx.bin", "name": "dsstdfx" }]

imageBuild

Type: RxdkImageBuildOptions · Optional

Switches for the PE→XBE step (imagebld). Omitted keys use imagebld defaults — see Image build options.

prebuilt

Type: RxdkPrebuiltConfig · Optional — presence switches the project to prebuilt-XBE mode

When set (with a valid xbe), RXDK does not compile. sources/libraries/imageBuild are ignored. See Prebuilt-XBE projects and prebuilt fields.

Multi-project builds (libraries)

A larger title can be split into a main executable plus one or more static-library projects it reuses. Each library is an ordinary project with "type": "library" that builds to out/<name>.lib; the executable lists the libraries in projectReferences.

When you build the executable, RXDK automatically:

  • resolves projectReferences transitively (libraries may reference libraries) and builds them in dependency order (cycles are reported);
  • adds every referenced library's publicIncludePaths to the compile include path;
  • links the built .libs (in a link group, so inter-library references resolve regardless of order) and merges each library's SDK libraries into the final link (deduplicated, libkernel.lib kept last).

A library project never links anything itself, so its libraries only matter to the executable that references it. A referenced library's manifest is read using its own defaultConfiguration (or its first configuration), not the configuration the executable is building. If that configuration's <outputDir>/<name>.lib already exists it is linked as-is; otherwise RXDK builds it, compiling Debug or Release to match the executable. After changing a library's sources, build the library's own folder (or delete its .lib) so the executable doesn't link a stale copy. For the SDK libraries the simplest rule is the one the templates follow: list every SDK library, including libcpp.lib/libcppd.lib when the library's code or the SDK libraries it uses are C++, in the executable's per-configuration libraries, and give library projects no libraries of their own.

Library — libs/mathlib/rxdk.project.json:

{
  "name": "mathlib",
  "type": "library",
  "sources": ["src/mathlib.cpp"],
  "publicIncludePaths": ["include"],
  "defaultConfiguration": "Debug",
  "configurations": {
    "Debug":   { "configuration": "debug",   "outputDir": "out/Debug" },
    "Release": { "configuration": "release", "outputDir": "out/Release" }
  }
}

Executable — game/rxdk.project.json:

{
  "name": "mygame",
  "sources": ["src/main.cpp"],
  "projectReferences": ["../libs/mathlib"],
  "imageBuild": { "debug": true, "stackSize": 65536 },
  "defaultConfiguration": "Debug",
  "configurations": {
    "Debug": {
      "configuration": "debug",
      "libraries": ["libd3d8d.lib", "libxapid.lib", "libcd.lib", "libcppd.lib", "libkerneld.lib", "libcompatd.lib"],
      "outputDir": "out/Debug"
    },
    "Release": {
      "configuration": "release",
      "libraries": ["libd3d8.lib", "libxapi.lib", "libc.lib", "libcpp.lib", "libkernel.lib", "libcompat.lib"],
      "outputDir": "out/Release"
    }
  }
}

src/main.cpp can now #include "mathlib.h" (from the library's include/) and call into it — the header resolves in the editor and at build time, and the symbol is linked from mathlib.lib. Building the library folder directly produces just its .lib; Deploy/Run on a library are no-ops.

Notes & gotchas

  • One manifest per project. The extension uses the first rxdk.project.json it finds. Keep one project per workspace folder.
  • sources are not globbed. Add new files to the array explicitly.
  • Strict JSON. No // comments or trailing commas.
  • After editing the manifest, re-run RXDK: Build (and Deploy) so new sources/assets take effect.
