Library projects & references

← Overview

Creating a library

Add an Original Xbox Lib project to your solution (File > New > Project, or Add > New Project). It builds to a static .lib. Put its public headers under include and list that folder in Xbox Build > Public Include Directories so referencing projects pick them up automatically.

Referencing a library

In the executable project, right-click References > Add Reference…, check the library project, and click OK. That is all — no metadata to edit and no properties to set:

  • RXDK builds the library before the executable and links its .lib automatically (the reference drives the link).
  • The reference is treated as build-order-only by default, so it never shows the "cannot be resolved" warning that a plain Makefile-project reference otherwise would.
  • The library's public include folder is added to the executable's include path.

The multi-project Cube and Music Visualizer templates are set up exactly this way and are a good reference.

Linking an external prebuilt library

To link a .lib that isn't an RXDK project (a prebuilt static library), use Xbox Build > Linker:

  • Additional Dependencies — the .lib file(s) by path (project-relative or absolute).
  • Additional Library Directories — extra folders to resolve Libraries names from, searched after the SDK lib dir (for linking your own libs by name).

External libraries must be built for the Xbox target (the RXDK GNU/clang ABI); an incompatible .lib will fail at link time.
