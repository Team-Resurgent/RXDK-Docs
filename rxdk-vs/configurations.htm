Debug and Release

RXDK projects ship with the standard Debug and Release configurations. Debug builds unoptimized with debug info (-O0 -g) and links the debug SDK libraries; Release builds optimized and links the release libraries.

Build Flavor & Release Optimization

On Configuration Properties > Xbox Build:

  • Build Flavor — Debug or Release. This is what decides debug-vs-release (SDK lib variant + optimize base), rather than the configuration's name. It defaults from the name (the Debug config is Debug-flavored, everything else Release-flavored), but you set it explicitly for a custom configuration.
  • Release Optimization — for Release-flavored configs, the Zig optimize mode: ReleaseFast (default, fastest runtime), ReleaseSafe (runtime safety checks), or ReleaseSmall (smallest size). Ignored for Debug.

Custom configurations

To add your own configuration (e.g. "MyApp"), use Build > Configuration Manager > New and copy from Debug or Release. Then, on the Xbox Build page for that configuration, set:

  • Build Flavor — Debug or Release.
  • Preprocessor Definitions — extra macros (on top of the built-in _XBOX;XBOX).
  • Libraries — the SDK libs to link.

Every field on the RXDK pages is per-configuration, so each configuration can differ. Use the Configuration dropdown (or "All Configurations") at the top of the Property Pages dialog.

Output directory

Build output goes to out\<Configuration>\ — for example out\Debug\, out\Release\, or out\MyApp\ — so different configurations don't overwrite each other. The General page's Output Directory reflects this. The location is controlled by the RxdkOutDir property (default out\$(Configuration)) if you need to change it.
