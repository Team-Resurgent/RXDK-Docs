Deploy & debug

← Overview

F5

Press F5 — or the green Xbox Debugger (RXDK) run button. RXDK builds the startup project, deploys the .xbe and its media to the console, launches the title, and attaches a source-level debugger over xbdm. Set breakpoints in your source; when one is hit Visual Studio stops with the source shown and the Call Stack, Locals, Watch and Registers windows live from the console.

The green button reads Xbox Debugger (RXDK), not "Local Windows Debugger" — that is expected. Do not use a Local Windows Debugger; the .xbe is not a Windows executable.

Set the startup project

F5 debugs the solution's startup project (bold in Solution Explorer). For a multi-project solution, make the executable the startup project (right-click > Set as Startup Project) — not the library.

Re-deploying (retry) & the project menu

Right-click an RXDK project in Solution Explorer for per-project commands:

  • Deploy to Xbox — build (incrementally) and (re)deploy the .xbe and media. Use this to retry a deploy when the devkit was off during F5, without a full rebuild.
  • Remove DXT & Reboot — for DXT projects only; removes the extension from E:\dxt and warm-reboots.

DXT (debug-monitor extension) projects

A DXT is not a title — it is loaded by xbdm at boot from E:\dxt. F5 on a DXT project builds, deploys to E:\dxt and warm-reboots the console; there is no attach-debug session because the extension runs inside the debug monitor. Use Remove DXT & Reboot to unload it.

Optimized (Release) builds

Debugging works in any configuration, but a Release-flavored build is optimized, so stepping and Locals are less precise — as with any optimized native build. Use Debug for the most faithful debugging.
